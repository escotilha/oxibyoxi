# v0.1.0b2 — 2026-04-26

**The "engine grows up" cut.** 85 commits since `0.1.0b1`. b1 was the first wheel a stranger could pip-install; b2 is the first wheel that actually carries the engine through a full dogfood loop end-to-end — multi-model orchestration scaffolding, the auto-improve subsystem, the continuous-dispatch supervisor, and the install fixes that close the fresh-install zero-tasks gap.

## Headline

**`oxi v3 saturate` — continuous-dispatch supervisor.** The bash supervisor pattern (`~/.oxi-supervisor.sh` running in tmux) is now a first-class CLI subcommand. `saturate --concurrency N --max-cost-per-day USD` loops `ingest_roadmap → auto_observe → seed_from_roadmap → dispatch_loop` until budget, killswitch, or SIGTERM stops it. Daemon-ready with PID file, signal-safe shutdown, daily-budget hard exit. Replaces the bash supervisor entirely; can be wrapped by launchd/systemd/tmux with no shim. (#180)

**`oxi v3 tick` ingests + seeds.** Until this cut, only `saturate` populated the planned-task queue from the roadmap; a single tick was reconciliation-only and a fresh install with valid roadmap.md saw `task counts: (no tasks)` after the README's smoke step. Tick now mirrors saturate's queue-population contract at the head of every iteration, so the README's onboarding sequence ends with a populated queue without needing the full supervisor loop. (T2-48, this cut's commit `3f80101`)

## Multi-model orchestration scaffolding

The agentic worker is still Claude (`claude -p` in a worktree) but the inference path got rebuilt around an `InferenceGateway` abstraction so non-agentic roles (planner, classifier, ranker, dedup, summary) can route to any provider LiteLLM speaks.

- **Agentic adapter protocol** with `ClaudeCodeAdapter` shim — re-exports today's `dispatch_invoke.py` through a Protocol that future `CodexCliAdapter` will plug into. Zero call-site changes; new `model_id`, `usage_normalizer`, `tool_translator` hooks land as identity functions on the Claude path. (T2-30)
- **Codex adapter skeleton** with version-pin smoke test — spawns `codex exec --json` via the same isolation pattern as `dispatch_invoke.py`; format-drift detection on init. (T2-31, #147)
- **Codex JSONL event parser** mapping codex events to oxi's canonical event types. Pure functions, exhaustively tested with recorded fixtures. (T2-32, #154)
- **Inference gateway client** with non-streaming cost-header lock. Reads `x-litellm-response-cost` per call. (T2-37, #173)
- **`routing.py` + `defaults/routing.yaml`** — pure `route_for(role, task) -> ModelChoice` function backed by YAML. Roles are `worker`, `critic`, `heartbeat-triage`, `prompt-injection-screen`. (T2-39, #172)
- **xAI Grok as InferenceGateway target** via LiteLLM — provider block, rate cards, virtual key. Reachable through `route_for("heartbeat-triage")` or any role config-swappable. (T2-41, #182)
- **OpenRouter as InferenceGateway target** via LiteLLM — handles OpenRouter's `usage.total_cost` quirk vs LiteLLM's standard cost header. (T2-42, #197)
- **Mac Mini LiteLLM gateway integration** + key-provisioning runbook at `docs/runbooks/litellm-gateway.md`. (T2-36, #194)
- **Model fallback chain on rate-limit exhaustion.** When `claude -p` exhausts its rate-limit retry on Opus, oxi records the exhaustion in the ledger and walks the per-tier fallback chain on the next dispatch (Opus → Sonnet → Haiku for max plans; Sonnet → Haiku for standard). 6-hour window prevents stale rate-limit state from holding a task on Haiku forever. (#92)

## Auto-improve subsystem

A new background loop that proposes roadmap items from external signals (org release feeds, topic queries) and self-pauses if its proposals stop converting.

- **`auto_external` package skeleton** + adapter protocol method + CLI subcommand stubs (`oxi v3 auto-improve scan|unpause|status`). (T1-B1)
- **GitHub source fetcher** for org release feeds and topic queries. (T1-B2, #162)
- **Ranking pipeline** (no LLM yet) — deterministic verdicts keyed by candidate ID. (T1-B5, #187)
- **Three-layer dedup** — identifier (monotonic counter), semantic (cosine ≥ 0.85 against open `front` rows + 30-day task history), temporal (same `(signal_kind, target_identifier)` within 14 days). (T1-B7, #189)
- **Claude Code Routine config + entry-point script** — runs daily via Routines; falls back to GitHub Actions cron if Routines GA slips. Credentials via Anthropic Managed Agent Vaults. (T1-B10, #160)

## Dispatch reliability

- **Bounded-parallel `dispatch_loop`** — fan out concurrent dispatches up to the adapter's per-host budget, no more synchronous serialization. (#135)
- **Repeat-failure escalation** — tasks that fail >2 times automatically get re-prompted with a decompose-first instruction. (#148)
- **Max-turns bump** 30 → 60 — earlier ceiling prevented workers from reaching the commit/push step on multi-file changes. (#137)
- **Workers commit incrementally** — prompt update steers `claude -p` to commit each logical unit instead of a single end-of-task commit, so partial work is recoverable when ship_recovery kicks in. (#146)
- **CPU-aware concurrency probe** — RAM-only envelope was over-recommending workers on busy hosts. Final recommendation: `min(ram_envelope, cpu_envelope, plan_tier_envelope, ceiling)`. (T2-43, #174)
- **WORKER_MEM_GB calibration** 1.5 → 0.5 to reflect actual worker RSS (the prior estimate was 3x reality and capped concurrency unnecessarily on smaller hosts). (#149)

## Onboarding fixes (2026-04-26 dogfood)

Caught during a stranger-from-clean-clone dogfood walkthrough. Each one is a real install-time wall someone hit.

- **macOS Python 3.9 cliff** — README + install runbook now lead with `brew install python@3.13` + an explicit-interpreter venv, plus a callout matching the exact pip error string (`Could not find a version that satisfies the requirement oxi-core`). The previous snippet ran against system `python3` which silently filters every release. (commit `9204507`)
- **Wizard scaffolds `.env` with OXI_ADAPTER pin** — when the bundled `_self` adapter or any other oxi adapter is installed, fresh wizard scaffolds couldn't run because of "multiple adapters installed." The `.env` pin lives next to the adapter; direnv/dotenv pick it up automatically. (commit `831fc4a`)
- **Wizard scaffolds `.env.example`** documenting non-agentic provider keys (`LITELLM_VIRTUAL_KEY_OPENROUTER`, `LITELLM_VIRTUAL_KEY_XAI`, `OXI_INFERENCE_GATEWAY_URL`). The wizard's "Claude plan tier" prompt was reading as if the whole engine was Anthropic-only; the multi-provider `InferenceGateway` capability wasn't surfaced anywhere in the install flow. (commit `a7aec81`)
- **README + runbook clarify agentic vs non-agentic split** — agentic worker (`claude -p`) is Anthropic-only; non-agentic InferenceGateway speaks Anthropic, OpenRouter, xAI/Grok via LiteLLM. (commit `f34797c`)
- **`AGENTS.md`** — installer instructions structured for AI coding agents (Claude Code, Cursor, Aider, Codex, Grok with shell access). Each step has a verification command, expected output, and a "common failures" block sourced from real bugs. Lives alongside the README. (commit `8768dc6`)
- **`release.yml`** — manual-trigger PyPI publish workflow via OIDC Trusted Publishing. No long-lived secrets in GitHub Secrets; tokens minted per-run by PyPI, scoped to oxi-core. `workflow_dispatch` only — first invocation is human-supervised. (commit `61f6264`)
- **T2-48 — `oxi v3 tick` now ingests + seeds.** This is the actual fix for the b1 zero-tasks blocker. (commit `3f80101`)
- **Self-adapter targets renamed `escotilha/oxibyoxi`** after the repo rename from `oxi`. (commit `f225a0e`)
- **`.gitignore` excludes local dogfood scaffold** so contributors don't accidentally commit `oxi-adapter-oxibyoxi/`. (commit `a601e81`)

## What "beta" means (unchanged)

- No breaking changes within `0.1.0b*`. Adapters that work on `0.1.0b1` work on `0.1.0b2`.
- Adapter protocol is frozen until `0.2.0a*`.
- Auto-merge defaults stay off. Operators opt in per `DispatchPolicy().auto_merge`.

## Install

```bash
# Need Python 3.11+. macOS ships 3.9 — install a newer one first:
#   brew install python@3.13     (macOS, recommended)
python3.13 -m venv .venv && source .venv/bin/activate
pip install --pre --upgrade oxi-core      # picks up 0.1.0b2
# or pin:
pip install oxi-core==0.1.0b2
```

`--pre` remains required (still in beta).

For AI agents performing the install on behalf of a user, see `AGENTS.md` at the repo root.
